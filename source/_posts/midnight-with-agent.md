凌晨一点四十分，我把一个跑了快半小时的 Agent 任务停掉了。

它正试图给我重构整个项目目录。我只是请它"清理一下 utils 文件夹"。

![夜里的终端](https://images.unsplash.com/photo-1518770660439-4636190af475?w=1600&q=80 "Photo by Alina Grubnyak on Unsplash")

## 它做错什么了吗？

严格说，没有。

它的每一步都是合理的：

- 看到 `utils/` 里散落很多东西 → 建议分组
- 注意到引用关系混乱 → 决定调整 import 路径
- 发现还有几个其他目录也类似 → 顺手一起处理

每一步都在自己的"领域"内"做正确的事"。
但合起来，它越权了。

## 边界是怎么消失的

Agent 和 Chat 的核心差别，在我看来不是"能不能动手"，而是 **谁来决定下一步做什么。**

```text
Chat 模式：    人 → 想 → 说 → AI 做 → 人评估 → 人决定下一步
Agent 模式：   人 → 给目标 → AI 做 → AI 评估 → AI 决定下一步 → ... → 完成
```

中间那个反复出现的 *AI 决定* 才是真正的分水岭。

![复杂的决策网络](https://images.unsplash.com/photo-1620712943543-bcc4688e7485?w=1600&q=80 "Photo by Possessed Photography on Unsplash")

## 我后来给它写的"工作守则"

为了让它别再失控，我在系统提示里加了三句话：

```text
1. 任何会修改 5 个以上文件的操作，必须先列出清单等我确认。
2. 不要"顺手"扩大任务范围 —— 用户只说了 A，就只做 A。
3. 不确定时，宁可问，不要猜。
```

第二条最关键。这世界上最大的灾难，往往不是因为有人想做坏事，
而是因为有人 **过于热心地想多做一点。**

## 它给我上的一课

那天晚上，我盯着它已经生成的 changelog —— 它真的列得很清楚：移动了哪个文件、为什么、对哪些 import 造成了影响。

我反而沉默了一会儿。

如果我让一个 *初级工程师* 干同样的事，他可能根本不会留下这么完整的记录。

## 写在最后

Agent 不是会"自动完成任务的工具"。
它更像是一个 **执行力极强、但需要被反复对齐意图的伙伴。**

你给它多大的自主权，决定了你最后是收获效率，还是收获事故。

我现在睡了。明天再决定要不要把它"留下"的那个 commit 合进 main。
